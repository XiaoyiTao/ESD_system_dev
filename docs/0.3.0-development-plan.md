## 三、6 態狀態機（0.3.0 核心設計）

### 3.1 正式枚舉

| 數值 | 枚舉 | 中文 | 含義 |
| ---: | --- | --- | --- |
| 10 | `AVAILABLE` | 庫存 | 已入庫，可發放 |
| 20 | `ISSUED` | 發放中 | 已交付員工，必有持有人 |
| 25 | `PENDING_LAUNDRY` | 待送洗 | 已回收、等待送洗，無持有人 |
| 30 | `IN_LAUNDRY` | 清洗中 | 送洗中，無持有人 |
| 40 | `RETIRED` | 報廢 | 終止狀態 |
| 50 | `LOST` | 丟失 | 終止狀態 |

### 3.2 流轉矩陣

```
[新入庫]  → 庫存(10)
庫存(10)   → 發放中(20)  發放
發放中(20) → 庫存(10)    回收/直接入庫
發放中(20) → 待送洗(25)  回收/送洗
待送洗(25) → 清洗中(30)  送洗登記（開始清洗）
清洗中(30) → 庫存(10)    完成清洗（clean_count+1）
庫存/發放中/待送洗/清洗中 → 報廢(40)  報廢登記
庫存/發放中/待送洗/清洗中 → 丟失(50)  丟失登記
報廢/丟失  → 前態        撤銷（恢復快照）
```

關鍵差異：**回收選「送洗」不再直接進入「清洗中」，而是先進入「待送洗」**；清洗管理頁面將待送洗物品送洗後才進入「清洗中」。

### 3.3 狀態不變式

1. `AVAILABLE`：持有人為空，無進行中的發放/清洗記錄。
2. `ISSUED`：持有人有值，恰一筆 `ACTIVE` 發放記錄。
3. `PENDING_LAUNDRY`：持有人為空，恰一筆 `ACTIVE` 清洗記錄（未開始洗），不得再次回收或送洗。
4. `IN_LAUNDRY`：持有人為空，恰一筆 `ACTIVE` 清洗記錄（清洗中）。
5. `RETIRED`/`LOST`：持有人為空，不得發放/回收/完成清洗。
6. 完成清洗同一事務內 `clean_count+1` 並將清洗記錄標為 `COMPLETED`。

## 四、0.3.0 交付範圍

1. **狀態機改造**：6 態枚舉、流轉白名單、DB 約束、前端映射、狀態機單元測試更新。
2. **發放管理**：單筆發放（庫存→發放中）、發放快照補充「工號/姓名/責任主管/課別/樓層」（從人員庫讀取）、發放列表按資產展示全部歷史記錄（一資產多次發放全部顯示）。
3. **回收管理**：回收（發放中→庫存 或 發放中→待送洗），去掉「回收狀態」欄位，結算對應發放記錄。
4. **清洗管理**：送洗登記（待送洗→清洗中）、完成清洗（清洗中→庫存，clean_count+1）；完成後從頁面消失，去掉「清洗歷史」頁籤。
5. **資產詳情**：發放歷史、清洗歷史只顯示最近一次。
6. **併發控制**：發放/回收/完成清洗以條件更新（`lifecycle_status`+`version`）原子搶佔，單資產雙發放只允許一次成功。
7. **人員管理修正**：移除衣/鞋數量展示。
8. **RBAC 修正**：普通用戶僅查看+導出（首頁/報警/人員/資產），其餘頁面隱藏。

### 4.1 明確不納入 0.3.0

- Excel 導入/導出（0.5.0）
- 報警中心、Dashboard（0.4.0）
- 報廢/丟失/撤銷（0.4.0）
- 報表中心、庫存管理（已裁剪，不再開發）
- 帳號設置（走 platform-system-server-master 統一後台，非本服務）
- 備份恢復（已取消）
